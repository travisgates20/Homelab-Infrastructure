# Security Hardening

## Overview

Security controls within the homelab are implemented through centralized Group Policy and are separated according to system role.

Dedicated security baselines are maintained for:

- Domain controllers
- Domain-joined workstations

This separation allows security controls and auditing requirements to be applied based on the role and risk profile of each system.

## Group Policy Design

Security configuration is maintained using dedicated Group Policy Objects rather than placing all security configuration within the default domain policies.

Current security GPOs include:

- `LAB - Domain Controller Security Baseline`
- `LAB - Workstation Security Baseline`

The domain controller baseline is linked to the Domain Controllers OU, while the workstation baseline is linked to the Workstations OU.

This design provides separation between infrastructure roles and allows each baseline to evolve independently.

## Advanced Audit Policy

Advanced Audit Policy is used to provide detailed security event logging.

The following policy is enabled:

`Audit: Force audit policy subcategory settings to override audit policy category settings`

This ensures that granular Advanced Audit Policy settings take precedence over legacy category-level audit settings.

## Domain Controller Security Baseline

Domain controllers use an audit baseline focused on authentication, directory services, account management, privilege use, policy changes, and system integrity.

### Account Logon

Success and failure auditing is enabled for:

- Credential Validation
- Kerberos Authentication Service
- Kerberos Service Ticket Operations

### Account Management

Success and failure auditing is enabled for:

- Computer Account Management
- Other Account Management Events
- Security Group Management
- User Account Management

### Directory Service Access

Success and failure auditing is enabled for:

- Directory Service Access
- Directory Service Changes

This provides visibility into security-relevant access and modifications within Active Directory.

### Logon and Logoff

Auditing includes:

- Account Lockout — Failure
- Logoff — Success
- Logon — Success and Failure
- Special Logon — Success

### Policy Change

Success and failure auditing is enabled for:

- Audit Policy Change
- Authentication Policy Change
- Authorization Policy Change

### Privilege Use

Success and failure auditing is enabled for:

- Sensitive Privilege Use

### System

Auditing includes:

- Security State Change — Success
- Security System Extension — Success and Failure
- System Integrity — Success and Failure

## Workstation Security Baseline

Domain-joined workstations use a separate baseline that combines security auditing with endpoint hardening and enhanced security telemetry.

### Session Security

The workstation baseline configures a machine inactivity limit of:

`900 seconds`

This limits unattended authenticated sessions.

### Process Creation Auditing

Process creation auditing is enabled to provide visibility into processes executed on domain-joined workstations.

Command-line arguments are included in process creation events to provide additional context during security monitoring and investigation.

### Microsoft Defender Antivirus

Microsoft Defender Antivirus is centrally configured through Group Policy.

Current controls include:

- Defender Antivirus remains enabled
- Downloaded files and attachments are scanned
- Real-time protection remains enabled
- Behavior monitoring is enabled

These controls provide centrally enforced endpoint malware protection.

### Cloud-Delivered Protection

Microsoft Active Protection Service (MAPS) integration is enabled using Advanced MAPS membership.

Automatic sample submission is enabled when additional analysis is required.

This provides additional cloud-based threat detection capabilities.

### PowerShell Logging

Enhanced PowerShell logging is enabled to improve visibility into administrative and potentially malicious PowerShell activity.

Current controls include:

- PowerShell Module Logging
- PowerShell Script Block Logging

Module logging records PowerShell module and command activity.

Script Block Logging records PowerShell script content for security monitoring and investigation.

## Security Monitoring

The audit configuration is designed to generate security-relevant telemetry that can later be integrated with centralized logging and monitoring infrastructure.

Events generated by the current configuration provide visibility into areas including:

- Authentication attempts
- Account changes
- Group membership changes
- Active Directory changes
- Privileged activity
- Policy modifications
- Process execution
- PowerShell activity
- System integrity events

## Design Principles

The security architecture follows several core principles:

- Centralized policy enforcement
- Role-specific security baselines
- Least privilege
- Increased visibility into privileged activity
- Enhanced authentication auditing
- Endpoint protection
- Security-focused logging
- Incremental hardening and validation
